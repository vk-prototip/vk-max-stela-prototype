# Веб-прототип стенда VK и MAX

Интерактивный прототип на React, TypeScript и Vite. Внутренний холст фиксирован на 1080 × 1920 и пропорционально масштабируется под окно браузера.

Публичная версия: <https://vk-prototip.github.io/vk-max-stela-prototype/>

Выпуск от 2026-10-04 включает актуальную механику, Max Sans и исправления дизайн-аудита D-063. Публикация по прямому запросу пользователя выполняется существующим workflow GitHub Pages при обновлении `main`.

## Запуск

Нужен Node.js 24 или новее с npm. В Windows можно запустить прототип двойным кликом по `start-prototype.bat`. При первом запуске батник установит зависимости, запустит локальный сервер на фиксированном порту 5173 и откроет браузер.

Локальный адрес: <http://127.0.0.1:5173/vk-max-stela-prototype/>. Если порт занят другим процессом, сначала нужно освободить его либо явно согласовать другой порт; `strictPort` не переключает проект на случайный адрес.

Запуск из терминала:

```powershell
npm install
npm run dev
```

Проверка перед передачей:

```powershell
npm run typecheck
npm run test
npm run lint
npm run build
npm run check:deliverable
```

## Вход в проект без истории диалога

`check:deliverable` проверяет отсутствующие ссылки и неиспользуемые ресурсы, исходники и временные файлы в корне, а также чрезмерно большие файлы. Проверка использует рабочую папку, включая ещё не добавленные в Git файлы; она не заменяет визуальную проверку браузера.

1. Прочитать `docs/PROJECT_RULES.md` и локальный `AGENTS.md`. Все обязательные правила включены в репозиторий; соседний `../AGENTS.md` для работы не требуется.
2. Открыть `docs/PROJECT_STATE.md` – там зафиксирована текущая рабочая точка.
3. Открыть `docs/CHANGELOG.md` – там сохранён путь от инициализации до текущего состояния.
4. Проверить `docs/OPEN_QUESTIONS.md` перед изменением логики или текста.
5. Использовать `docs/NAVIGATION.md` как карту кода и источников.
6. Для передачи проекта разработчикам прочитать `docs/MECHANICS.md`: там маршруты, обе шкалы баллов, контракт событий версии 2 и границы интеграции.
7. Для механики ИИ-обложек открыть `docs/AI_COVERS.md`: матрица жанров, правило выбора обложки, базовый план контента и отдельные условия третьего вопроса Discovery. Базовый пул top 3 прямо закреплён сценарием. В Q-018 остаётся только способ включения отдельного сюрприза Discovery в базовый план продюсера, а не вопрос о количестве базовых тематик.
8. Независимый аудит по `docs/AUDIT_BRIEF.md` выполнен 2026-10-04; результаты и ограничения – в `docs/AUDIT_REPORT.md`. Локальная документация описывает реализацию и не заменяет свежую проверку первичных источников. Продуктовые исправления по итогам аудита не вносились.

## Данные для других экранов

Каждый ответ публикует событие с метаданными. Первые два ответа VK Видео также передают независимые дельты видео-тематик и жанров ИИ-обложек; итоговая рекомендация содержит зафиксированное распределение жанров, базовый план контента и структурированное условие третьего ответа. Контракт имеет `version: 2`, выбора М/Ж и поля `gender` больше нет.

После первых двух ответов выбираются три ведущие тематики; если на границе две темы имеют по одному баллу, третья выбирается случайно. Для условия Discovery «из тематики 3 или 4» используются только положительные темы из таблицы исходов: при трёх положительных темах кандидат один, при четырёх два. Нулевая четвёртая позиция полного диагностического ранжирования не добавляется. Максимум 12 единиц контента – верхняя граница базового плана, не обязательный объём каждой подборки.

В локальном прототипе события получают обработчик `vk-stela:event` в текущей вкладке и `BroadcastChannel('vk-stela')` в другой вкладке того же сайта. Внешние экраны инсталляции пока не подключены: адрес и протокол передачи должны быть согласованы отдельно. Формат событий, пример подписки и правила пересчёта описаны в `docs/MECHANICS.md`. Камера, генератор изображений и каталог роликов не подключены; вычисленные планы не означают, что изображения и видео уже созданы или получены.

## Рабочие файлы и архив

Для публикации рабочая версия фиксируется в Git и отправляется в `main`. При продолжении работы проверять локальные изменения через `git status`; не делать reset и не заменять рабочие файлы скачанной версией.

В `src/assets/` хранятся подключённые рабочие ресурсы, включая веб-шрифты. Для запуска после скачивания репозитория не нужны установленные VK/Max Sans, Figma, соседние папки или клиентские исходники. `docs/SOURCE_REGISTER.md` содержит ссылки на источники и даты сверки; `docs/FIGMA_CJM.md` и `docs/GOOGLE_DOC_COPY.md` оставлены как исторические материалы, а не текущая спецификация.

При локальной уборке оригиналы, неиспользуемые ресурсы и прежний код сохранены отдельно, без изменения их содержимого, в `../05_Веб-прототип_исходники-2026-10-04/`. В `sources/` находятся пользовательские экспорты и бриф, в `unused-assets/` и `legacy-code/` – исключённые из сборки файлы, в `documentation/` – прежний полный `PROJECT_STATE.md`. Манифесты SHA-256 находятся рядом. Этот архив не является зависимостью приложения и не входит в GitHub ZIP. Подробная карта – в `docs/NAVIGATION.md`.
