# Механика прототипа стелы

Актуально на 2026-10-01. Это описание поведения, которое можно проверить в коде и тестах. Оно не описывает внешний вид стенда и не утверждает, что физические экраны уже подключены.

## Маршруты

1. Старт: выбор VK Видео или MAX, затем онбординг. Озвучка и распознавание отсутствуют, выбор делается нажатием.
2. MAX: аудитория, затем цель, затем одна из четырёх миссий. `access` всегда ведёт к Цифровому ID, `connection` к общению. `visibility` ведёт к блогеру для личного пользования и к продвижению бизнеса для бизнеса. Это прежнее согласованное правило.
3. VK Видео: вопрос про вечер, вопрос про идеальный контент, вопрос про режим Discovery. Первые два ответа добавляют баллы тематикам, все три отправляют теги.
4. Выбор 3.1, 3.2 или 3.4 ведёт к финалу. Только 3.3 «хочу стать героем VK Видео» открывает предложение фото. «Да, давайте» ведёт к выбору «М»/«Ж», затем к имитации сканирования. «Назад» с выбора пола возвращает к фото и снимает прежнее согласие. «Пропустить» обходит выбор пола и ведёт сразу к финалу. Камера и создание изображения не подключены.
5. Финальный экран воспроизводит текст из нового документа и оставляет прежнюю кнопку «спасибо» для сброса.

## Метаданные и доставка

`src/content/max.ts` и `src/content/vkVideo.ts` содержат массивы тегов для вариантов ответа из таблицы. Порядок и даже повторяющийся тег «культура» у варианта 2.3 сохранены. При пропуске фото `metadata` пустой по прямому указанию пользователя. У нового выбора «М»/«Ж» в таблице тегов нет, поэтому он отправляет `answer` с `questionId: 'gender'`, `answerId: 'male'` или `'female'` и пустым `metadata`. При выборе ответа `src/features/prototype/events.ts` создаёт событие `answer` с этими данными, идентификаторами сессии, вопроса и ответа. Для первых двух вопросов VK Видео в этом же событии есть `themeDelta` с `+2` и `+1`.

В браузерной версии событие доставляется двумя способами:

- `window`-событие `vk-stela:event` в текущей вкладке;
- `BroadcastChannel('vk-stela')` для других открытых вкладок того же сайта.

Это **рабочая локальная доставка между вкладками одного origin**, а не сетевое подключение физической стены. Реальный адрес, протокол, подтверждение доставки и повторная отправка ещё не определены. Для них выделен интерфейс `EventSink`; разработчик может заменить браузерную реализацию сетевым адаптером, не меняя сценарий и таблицы ответов. Не следует утверждать, что теги уже отправляются на реальные экраны инсталляции.

Типы событий (`StelaEvent`, версия `1`):

- `session-start`: новый маршрут, `product`.
- `answer`: `product`, `questionId`, `answerId`, `answerLabel`, `metadata[]`, опционально `themeDelta`.
- `answer-cleared`: выбор в вопросе снят при возврате назад; получатель удаляет прежний выбор этого вопроса.
- `vk-recommendation`: `scores` восьми тематик, `rankedThemes`, `selectedThemes` (первые три), `discoveryAnswerId`, правило из документа и `photoMode` (`included`, `skipped`, `not-requested`). Для согласия на фото добавлено `gender: 'male' | 'female'`. Отправляется после ответа 3.1/3.2/3.4, сразу после пропуска фото либо после выбора «М»/«Ж».

Каждое событие несёт `sessionId`, возрастающий `sequence` и `occurredAt` в ISO 8601. Получатель должен хранить текущий ответ по ключу `(sessionId, product, questionId)`: новый `answer` заменяет старый, `answer-cleared` удаляет его. При новой сессии прежние данные не смешиваются. BroadcastChannel не воспроизводит события, отправленные до открытия вкладки-получателя.

Проверка в консоли вкладки стелы:

```js
window.addEventListener('vk-stela:event', event => console.log(event.detail))
```

Проверка в другой вкладке того же сайта:

```js
const channel = new BroadcastChannel('vk-stela')
channel.onmessage = event => console.log(event.data)
```

## Баллы и Discovery

Восемь тематик перечислены в `vkThemes` ровно по документу. Каждый из первых двух ответов добавляет `+2` к основной тематике и `+1` к дополнительной. После двух ответов сумма баллов равна шести. Вопрос 3 и выбор фото баллов не добавляют.

`calculateThemeScores` возвращает все восемь тематик, включая нулевые. `rankThemes` сортирует по убыванию; при равенстве порядок внутри группы определяется случайно. В результат передаются три первых тематических выбора. Если на границе третьего места две темы с одним баллом, третья выбирается случайно, как указано в сценарии. Полный рейтинг остаётся в событии, потому что вариант 3.2 ссылается на тему 3 или 4.

Третий ответ определяет только инструкцию для рекомендательной системы:

| Ответ | Правило из документа | Что реально делает прототип |
| --- | --- | --- |
| 3.1 Похожее на любимое | По одному видео из топ-2 тематик | Отправляет идентификатор, рейтинг и правило |
| 3.2 Новое по интересам | Дополнительное видео из тематики 3 или 4 | Отправляет идентификатор, рейтинг и правило |
| 3.3 Стать героем | Пул обложек по выбранным темам с образом пользователя | Запрашивает необязательное фото; отправляет режим фото |
| 3.4 Популярное | Самое популярное видео за последние 7 дней из согласованного каталога | Отправляет идентификатор и правило |

Прототип не имеет каталога согласованных видео, счётчика популярности или генератора обложек и **не выбирает реальные видео**. При отказе от фото отправляет событие ответа с пустым `metadata` и `photoMode: 'skipped'`; изображение не создаётся. Выбор пола передаётся как структурированное поле, но пока не влияет на картинку и не присваивает тематических баллов. На экране фото исходная фраза сохранена с исправлением опечатки: «условия использования персональных данных» стали активной кнопкой. Она открывает прокручиваемую панель поверх экрана, не публикует событий и не принимает согласие. Утверждённый текст условий не предоставлен: по запросу пользователя панель содержит длинный явно обозначенный демонстрационный макет с разделами и списками, а не юридический текст. Камеры и юридически значимого согласия в прототипе нет.

## Проверка

`src/features/prototype/logic.test.ts` проверяет все 16 сочетаний первых двух ответов, контрольные значения матрицы и ничью за третье место. `events.test.ts` проверяет структуру событий, точные теги, дельты, выбор пола и отмену выбора. Для ручной проверки пройти оба маршрута, отдельно проверить 3.1, 3.2, 3.3 с обоими ответами на фото, оба варианта «М»/«Ж», 3.4 и возврат назад.
