# ИИ-обложки VK Видео

## Источники и границы

Матрицы баллов и соответствие тематик жанрам перенесены из последнего раздела [документа «VK Видео_Стелла»](https://docs.google.com/document/d/1ycQkS7hNhyWWG0AOPb6BhfpWThWD7FTD0b46i_ONRAE/edit?tab=t.0), проверенного 2026-10-03. Правило для Кино и Спорта подтверждено пользователем в этой задаче: больший балл среди жанров данной тематики, при равенстве случайно один из двух.

Прототип вычисляет жанры и выдаёт план контента, но не вызывает генератор, не снимает фотографию и не выбирает конкретные ролики. Для этого нужны внешний генератор и каталог согласованных видео. Вес видео-тем и вес жанров ИИ-обложек являются двумя независимыми шкалами.

## Соответствие тематик

| Тематика видео | Допустимые жанры ИИ-обложки |
| --- | --- |
| Наука | SCI FI |
| Культура и образование | HISTORY |
| Медиа и шоу | COMEDY |
| Музыка | MUSICAL |
| Игры и авто | BOEVIK |
| Спорт | DRAMA, HORROR |
| Новости и бизнес | DETECTIVE |
| Кино | FANTASY, ADVENTURE |

В исходной таблице соответствия используется `MUSICAL`, а в начислении баллов и итоговых матрицах написано `MUSICLE`. Это технический alias одного жанра, а не одиннадцатый жанр. `normalizeAiCoverGenre` явно преобразует `MUSICLE` в `MUSICAL`; во всех событиях и расчётных результатах используется только `MUSICAL`.

## Начисление баллов

Каждый перечисленный жанр получает всю указанную прибавку. Например, `drive` добавляет по 2 балла и BOEVIK, и ADVENTURE; не делит 2 балла между ними. Поэтому итоговая сумма баллов жанров равна 7 или 8, тогда как сумма баллов видео-тем после двух ответов всегда равна 6.

| Вопрос | ID ответа в прототипе | +2 каждому жанру | +1 каждому жанру |
| --- | --- | --- | --- |
| evening | series | FANTASY | HORROR |
| evening | standup | COMEDY | BOEVIK, MUSICAL |
| evening | interview | HISTORY | DRAMA |
| evening | science | SCI FI | ADVENTURE, DETECTIVE |
| ideal-content | drive | BOEVIK, ADVENTURE | нет |
| ideal-content | heroes | DRAMA, HORROR | нет |
| ideal-content | learn | DETECTIVE | HISTORY, SCI FI |
| ideal-content | rest | MUSICAL | FANTASY, COMEDY |

ID `standup`, `science`, `drive`, `heroes`, `rest` сохраняют совместимость с существующим прототипом. В документе эти же ответы обозначены словами comedy, documentary, thrill, empathy, relax; название ответа не является ключом расчёта.

Третий вопрос, согласие и пропуск фото не добавляют баллы к жанрам. Экран выбора М/Ж и поле `gender` удалены по прямому указанию пользователя.

## Выбор одного жанра на тематику

1. Пересчитать все десять жанров по двум текущим ответам, а не по числу полученных событий.
2. Взять подтверждённый вызывающей стороной список выбранных тематик видео. Функция распределения не выбирает число тематик сама.
3. Для каждой тематики рассматривать только жанры из таблицы соответствия. Если жанр один, выбрать его, даже если он получил 0 баллов.
4. Если жанров два, сравнить их накопленные баллы. Выбрать больший; при равенстве случайно выбрать один. Это применимо и к равенству 0:0.
5. Зафиксировать результат случайного выбора в `coverAllocation` и передать его в событие. Не повторять случайный выбор при ререндере или завершении анимации.

`rankedGenres` содержит все десять жанров, отсортированных по убыванию баллов. Равные баллы внутри этого диагностического списка сохраняют порядок исходной таблицы. Этот порядок не используется как правило выбора при равенстве: случайное решение отдельно записано в `themeSelections[].selectedGenre`.

## План контента

Событие рекомендации содержит `contentPlan` с `kind: 'producer-base-plan'`: это отдельно записанное уточнение продюсера, по два видео на каждую выбранную тематику. При `photoMode: 'included'` добавляется одна генерация на тематику, использующая выбранный для неё жанр; при `'skipped'` и `'not-requested'` генераций нет. План допускает не больше четырёх тематик и не больше 12 единиц контента.

`perTheme` хранит `theme`, `videoCount: 2`, `generationCount: 0 | 1` и `coverGenre` (null без фотографии). `videoCount`, `generationCount`, `total` и `limit: 12` на верхнем уровне позволяют проверить объём всей подборки. Эти числа описывают план, а не подтверждают получение роликов или генераций.

Размер базового пула подтверждён самим сценарием, это не открытый вопрос: top 3. После таблицы 16 исходов прямо указано: «Если тематик четыре из двух с 1 баллом (курсивом, серым в таблице) третьей берётся случайная». Первые два ответа дают три или четыре положительные темы; в случае 2,2,1,1 две ведущие темы сохраняются, а третья случайно выбирается из двух однобалльных. `selectTopThemes` реализует это без изменения утверждённых весов. Нулевые темы не добавляются. Максимум 12 единиц является верхней границей базового плана продюсера, а не требованием всегда получать 12 единиц или четыре темы. Функция распределения жанров принимает список тем извне; текущий сценарий передаёт top 3.

## Условия третьего вопроса

`discoveryInstruction` отдельно передаёт условия третьего вопроса из документа, а не только текстовую строку. Это декларативная инструкция будущему каталогу или генератору, не готовые ID роликов:

| Ответ | Структурированное правило | Статус |
| --- | --- | --- |
| familiar | По одному видео из каждой из первых двух тематик в `rankedThemes` | external-catalog-required |
| new | Одно дополнительное видео; кандидаты – третья и, если есть, четвёртая положительная тема из таблицы исходов. При трёх положительных темах кандидат только один; нулевая четвёртая тема исключена | external-catalog-required |
| popular | Один самый популярный ролик за последние 7 дней из согласованного каталога | external-catalog-required |
| hero | По одной обложке на выбранную тематику с уже зафиксированным жанром, только при включённом фото | external-generator-required, либо photo-not-included |

У всех четырёх правил `relationToContentPlan: 'unconfirmed'`. Эта пометка относится только к объединению двух отдельных описаний контента, а не к числу базовых тем или известным условиям третьего вопроса. Сам сценарий однозначно задаёт top 3 и перечисленные выше условия Discovery; дополнительное уточнение продюсера отдельно описывает базовый объём по два видео на тему. В прототипе оба описания передаются без скрытого сложения: инструкция не увеличивает `contentPlan.total`, не заменяет его количества и не выдаёт выдуманные ID роликов. Для настоящей сборки нужен внешний каталог согласованных видео; здесь нет оснований добавлять четвёртую нулевую тему или трактовать максимум 12 как обязательное количество.

Для вариантов `familiar` и `new` кандидаты берутся из ранжирования только после фильтрации `scores > 0`. Полное `rankedThemes` из восьми тем остаётся диагностическим полем события; нулевые позиции этого списка не являются дополнительными интересами пользователя. Третий вопрос изменяет инструкцию отбора контента, но не добавляет баллы к тематикам или жанрам ИИ.

## Контракт и вызовы

Новые события имеют `version: 2`: удалено поле `gender`, добавлены независимый `coverDelta` в ответах и обязательные `coverAllocation`, `contentPlan` и `discoveryInstruction` в рекомендации. `sessionId`, `sequence`, имена `vk-stela:event` и `BroadcastChannel('vk-stela')` сохраняются. Получателю, который проверяет `version === 1`, нужно обновить проверку и схему.

```ts
const coverDelta = getAiCoverDelta('evening', option.id)
publisher.answer('vk-video', 'evening', option, themeDelta, coverDelta)

const allocation = createAiCoverAllocation(answerIds, selectedThemes)
publisher.recommendation(
  calculateThemeScores(answerIds),
  rankedThemes,
  discoveryAnswerId,
  discoveryRule,
  photoMode,
  allocation,
)
```

`calculateAiCoverScores(answerIds)` возвращает все десять `{ genre, score }`; `rankAiCoverGenres(answerIds)` возвращает диагностическое ранжирование. Обе функции требуют ровно два корректных ID в порядке вопросов. `createAiCoverAllocation(answerIds, selectedThemes, random = Math.random)` позволяет подставить RNG в тестах. `createVkContentPlan(allocation, photoMode)` строит базовый план; publisher вызывает её автоматически и берёт `selectedThemes` из того же `allocation`, чтобы контракт не расходился с планом. `createDiscoveryInstruction(discoveryAnswerId, rankedThemes, allocation, photoMode, themeScores)` создаёт отдельную инструкцию третьего вопроса и исключает нулевые тематические кандидаты, также автоматически в publisher. Вызов `publisher.recommendation` остаётся шестипараметрическим.

`answer-cleared` отменяет предыдущий ответ вопроса. Получатель должен хранить текущий ответ по `questionId`, затем пересчитывать обе шкалы; простое сложение всей истории событий привело бы к двойному начислению после «Назад».

В событие копируются массивы и записи расчёта, поэтому последующие изменения локальных данных не изменяют уже переданный снимок.

## Файлы и проверка

- `src/content/aiCovers.ts`: исходное соответствие, прибавки и явная нормализация alias.
- `src/features/prototype/logic.ts`: чистые вычисления и план без внешней генерации.
- `src/types/prototype.ts`: типы жанров, распределения и плана.
- `src/features/prototype/events.ts`: доставка результата в событии version 2.
- `src/features/prototype/logic.test.ts`: независимые ожидаемые результаты всех 16 комбинаций, разделение шкал, обе границы случайного выбора, лимит и четыре инструкции Discovery; у всех 16 вариантов проверяется отсутствие нулевых кандидатов.
- `src/features/prototype/events.test.ts`: все восемь delta, 19 определений ответа без М/Ж, план с фото и без фото, отсутствие скрытого top 3 в транспорте, сохранность снимков, отсутствие двойного подсчёта Discovery и регрессия ложной четвёртой темы.

Реальная доставка на экраны инсталляции по-прежнему требует согласованного сетевого транспорта. Браузерная публикация не означает, что внешняя инсталляция уже получила данные.
